# 광주·전남 제철 음식 추천 - 데이터 수집

광주·전남 지역별 제철 음식/식재료를 사용자 취향에 맞게 추천하기 위한 공공데이터 수집 스크립트.

## 데이터 구조: 왜 두 축을 조합하는가

공공데이터포털에는 "광주·전남의 제철 음식"을 통째로 주는 단일 데이터셋이 없다.
대신 서로 다른 기관이 각각 다른 축을 제공한다.

| 축 | 데이터셋 | 제공기관 | data.go.kr API 유형 | 키 발급 상태 |
|---|---|---|---|---|
| 계절(농산물) | 이달의 음식 정보 | 농촌진흥청(농사로) | LINK | ✅ 발급 완료 (2026-07-28 승인) |
| 계절(수산물) | **없음 — 공공데이터 API가 존재하지 않음** | — | — | 수동 큐레이션 표로 대체 |
| 지역(전남) | 전남관광플랫폼(J-TaaS) 음식점 DB | 전라남도 | LINK | ✅ 발급 완료 — 단 **API 서버 장애 중** |
| 지역(광주) | 광주 대표 음식 정보 및 이미지 DB | 광주광역시 | LINK | ✅ 발급 완료 — 단 **API 서버 장애 중** |
| 지역(대체 소스) | 국문 관광정보 서비스(TourAPI) | 한국관광공사 | **REST** | ✅ 2026-08-03 승인 — **수집 완료** |
| 지역(수산물, 보강) | 품질인증수산물 | 국립수산물품질관리원 | LINK | ⏳ nfqs.go.kr 가입 필요 |
| 지역(외부 자료) | 전라맛도 음식데이터 엑셀 | 외부 제공 | **API 아님** | ✅ 확보 — 공공데이터 대조 후 등급 부여 |

인증키·발급 경로·문서 링크는 **`link_zip.md`**에 모아 두었다 (`.gitignore` 처리됨).

**중요**: 관련 데이터셋이 전부 data.go.kr `LINK` 유형이다. LINK 유형은 data.go.kr이 서비스키를
발급하지 않고 제공기관 사이트로 연결만 해주므로, 각 기관에 따로 가입해 키를 받아야 한다.

또 **계절 축에 수산물이 없다**는 점이 이 프로젝트의 구조적 공백이다. 농사로는 농촌진흥청
소관이라 농산물만 다루는데, 광주·전남은 해안권이고 전남은 수산물이 음식 정체성의 핵심이다.
월별 제철 수산물 공공데이터 API는 존재하지 않아 큐레이션 표로 메웠다
(아래 [제철 수산물](#제철-수산물-계절-축-수산물) 참고).

두 축을 식재료명/메뉴명·메뉴설명 텍스트 매칭으로 조인해 1차 매핑 후보를 만들고
(`src/process/build_seasonal_region_mapping.py`), 오탐은 사람이 검수해야 한다.

#### ⚠️ 가입 시 함정: 이메일에 TLD가 없어도 폼이 통과한다

폼이 `<input type="email">`을 쓰는데 HTML5 이메일 검증은 **최상위 도메인을 요구하지 않는다.**
`cweon611@gmail`처럼 `.com`이 빠져도 브라우저가 통과시키고, 서버는 존재하지 않는 도메인으로
메일을 보낸다. 반드시 주소를 끝까지 입력할 것.

| 입력값 | 브라우저 검증 |
|---|---|
| `user@gmail` (TLD 없음) | ✅ 통과 ← 함정 |
| `user@gmail.com` | ✅ 통과 |
| `broken@` | ❌ 거부 |

또 `/email/send`(인증메일 재전송) 페이지는 주소의 실재 여부와 무관하게 항상
`이메일 인증 메일을 전송했습니다`를 띄운다. 이 메시지는 **발송 성공의 근거가 아니다.**

#### ⚠️ redtable.global 플랫폼 전면 장애 (2026-07-30 확인)

전남·광주 **양쪽 토큰을 모두 발급받았고 인증도 통과하지만, 30개 엔드포인트 전부가
`DB_ERROR`를 낸다.** 두 사이트가 같은 플랫폼이므로 사이트별 문제가 아니라 플랫폼 공통 장애다.

| 요청 | 응답 |
|---|---|
| 키 없음 / 잘못된 키 | `401` `resultCode=30 SERVICE_KEY_IS_NOT_REGISTERED_ERROR` |
| **발급받은 정상 키** | `400` `resultCode=2 DB_ERROR` |

| 지역 | 결과 |
|---|---|
| 전남 | 17개 엔드포인트 전부 실패 (5회 반복 호출도 5/5 실패 — 간헐 아님) |
| 광주 | 13개 엔드포인트 전부 실패 |

키 검증을 통과한 뒤 DB 단계에서 깨지는 것이므로 **제공기관 서버 측 장애다.**
클라이언트에서 우회할 방법이 없음을 확인했다:
`pageNo`/`numOfRows` 조합, `Authorization` 헤더 방식, User-Agent/Accept 변경 모두 동일하고,
파라미터명은 `serviceKey` 정확한 표기만 인식한다(`ServiceKey`·`servicekey`는 401).

복구 여부는 아래로 확인한다 (전체 수집을 돌릴 필요 없이 1건만 찔러본다):

```bash
python -m src.collectors.redtable_region_food --check
```

정의서에는 에러코드 표가 없어 위 코드 의미는 실측으로 확인한 것이다.

발급받은 키는 `.env`에 채워 넣는다 (`.env.example` 참고).

## 파일 구조 — 핵심과 부수를 갈라 놓았다

**`src/process/`와 `src/data/`가 핵심이다.** 여기 있는 것만으로 매핑이 재생성된다.
검수·대조 도구는 `src/review/`로, 그 산출물은 `data/processed/review/`로 뺐다.
최종 결과물 하나만 `data/processed/` 바로 아래에 둬서 어느 게 본품인지 헷갈리지 않게 했다.

  collectors/
    nongsaro_monthly_food.py                 [핵심] 계절 축 · 농산물 수집

  review/
    build_seafood_review.py                  [부수] 수산물 표 검수 시트
    merge_jeollamatdo_food.py                [부수] 전라맛도 엑셀 x 공공데이터 대조

  raw/
    nongsaro_month_food_merged.json          [핵심] 계절 축 원본
    tourapi_jeonnam_raw.json                 [핵심] 지역 축 원본 ⚠️ 하루치 API 한도로 받은 것
    jeollamatdo_food.xlsx                    [부수] 외부 제공 엑셀

`detailIntro2`로 하나씩 받은 것인데 개발계정 일일 한도가 1,000건이라, 지우면 **다시 받는 데 하루가 걸린다.**

동작한 적이 없는 스텁이라 삭제했다. 필요해지면 `link_zip.md` 5절의 신청 링크에서 다시 시작하면 된다.

## 확정된 API 스펙

### 농사로 이달의 음식 (계절 축)
`http://api.nongsaro.go.kr/service/monthFd/{operation}?apiKey=...` — 응답 XML

오퍼레이션명·필드명은 농사로 배포 샘플코드(monthFd.zip)에서 확인했다.

| operation | 설명 | 파라미터 | 주요 응답 필드 |
|---|---|---|---|
| `monthFdYearLst` | 조회 가능 연도 | thisYear, thisMonth | year |
| `monthFdmtLst` | 이달의 **식재료** 목록 | thisYear, thisMonth | cntntsNo, `fdmtNm`(식재료명) |
| `monthNewFdLst` | 이달의 **음식** 목록 | thisYear, thisMonth | cntntsNo, `fdNm`(음식명), fdSeCode |
| `monthFdmtDtl` | 식재료 상세 | cntntsNo | ntrIrdntEfcyDtl(영양·효능), prchCheatDtl(구입요령), cstdyMthDtl(보관법) |
| `monthNewFdDtl` | 음식 상세 | cntntsNo | matrlInfo(재료), ckngMthInfo(조리법), energyQy 등 영양성분 |

#### ⚠️ 데이터가 있는 연도 (2026-07-30 실측)

**현재 연도로 조회하면 무조건 0건이다.** `date.today().year`를 쓰면 안 된다.

| 연도 | 커버리지 |
|---|---|
| 2016 ~ 2019 | **12개월 완전** (월별 식재료 약 3건 + 음식 약 12건) |
| 2015 | 5~12월만 |
| 2020 | 1~2월만 |
| 2023 | 10월에 식재료 1건뿐 |
| 2021·2022·2024~2026 | 없음 |

`monthFdYearLst`가 돌려주는 목록(2015~2020, 2023)은 **실제 데이터 보유와 다르다.**
2023은 목록에 있지만 사실상 비어 있다.

또 `thisMonth`는 **반드시 2자리 zero-padding**이어야 한다. `7`은 0건, `07`은 정상.

그래서 수집기 기본 동작(`collect_merged`)은 완전한 연도 4개(2016~2019)를 **월 기준으로 병합**하고
`cntntsNo`·이름으로 중복을 제거한다. 제철 식재료는 해마다 크게 바뀌지 않으므로 단일 연도보다
커버리지가 훨씬 좋다 (1월 기준: 단일 연도 식재료 3 / 음식 12 → 병합 후 10 / 54).

상세 조회는 항목당 1회씩 수백 번 호출되는데, 커넥션 재사용 없이 연타하면 농사로 서버가
연결을 끊는다(`ConnectTimeout`). `requests.Session` + 요청당 0.15초 페이싱 +
지수 백오프 재시도(최대 4회)로 처리했고, 상세 한 건이 실패해도 `detail={}`로 남기고 진행한다.

### redtable.global (지역 축 - 광주·전남)

두 기관이 같은 플랫폼을 쓰므로 **호출 규약은 같지만 응답 필드명이 다르다**.
각 사이트의 `OPEN API 정의서` PDF에서 확인했다.

공통 규약:
- REST(GET), 응답 **JSON**, SSL
- 요청 파라미터: `serviceKey`(필수, URL Encode), `pageNo`(옵션)
- 응답 봉투: `{"header": {resultCode, resultMsg, numOfRows, pageNo, totalCount}, "body": [...]}`
- `resultCode` `"00"` = `NORMAL_SERVICE`

수집에 쓰는 엔드포인트:

| 용도 | 전남 | 광주 |
|---|---|---|
| 식당 기본정보 | `/api/rstr/korean` | `/api/rstr` |

### TourAPI (지역 축 대체 소스 - 한국관광공사)

redtable이 플랫폼 전면 장애라 찾은 대체 소스. **data.go.kr REST 유형**이라 기관 사이트
별도 가입이 필요 없고 개발단계는 자동승인이다 (LINK 유형의 관문 문제를 피해간다).

데이터셋 https://www.data.go.kr/data/15101578/openapi.do ·
공식 문서 https://api.visitkorea.or.kr/#/useKoreaGuide

베이스 `https://apis.data.go.kr/B551011/KorService2` · JSON(`_type=json`) ·
공통 필수 파라미터 `serviceKey`, `MobileOS`, `MobileApp`

| 오퍼레이션 | 용도 | 핵심 파라미터 |
|---|---|---|
| `ldongCode2` | 법정동 코드 조회 | `lDongRegnCd` 생략 시 **전체 시도 목록** |
| `areaBasedList2` | 지역기반 목록 | `contentTypeId=39`, `lDongRegnCd` |
| `detailIntro2` | 소개 정보 | `contentId`, `contentTypeId=39` |
| `detailCommon2` | 공통 정보 | `contentId` (overview 등) |

**`contentTypeId=39`가 음식점**이고, `detailIntro2`가 이 타입에 대해 아래를 준다:

| 필드 | 의미 | 역할 |
|---|---|---|
| `treatmenu` | 취급메뉴 | **매칭의 핵심** — 메뉴명 목록 |
| `firstmenu` | 대표메뉴 | 특산/대표 메뉴로 취급 |
| `opentimefood` / `restdatefood` | 영업시간 / 쉬는날 | |
| `parkingfood` / `seat` / `packing` / `lcnsno` | 주차 / 좌석수 / 포장 / 인허가번호 | |

목록(`areaBasedList2`)은 `title`(상호), `addr1`+`addr2`, `mapx`(경도)/`mapy`(**위도**), `tel`을 준다.

⚠️ **지역코드를 하드코딩하지 않는다.** 데이터포털에 제공기관이 `전남광주통합특별시`로
등록돼 있어 행정구역 통합으로 법정동 시도 코드가 바뀌었을 수 있다. 그래서
`ldongCode2`로 전체 시도 목록을 받아 **이름으로 매칭**해 코드를 찾는다
(`TARGET_REGION_KEYWORDS`).

⚠️ **`menu_expln`을 비워 둔다.** redtable의 `MENU_EXPLN`은 '주재료' 목록이라 토큰
매칭에 의미가 있지만 TourAPI의 `treatmenu`는 '메뉴명' 목록이다. 취급메뉴를 개별 메뉴
레코드로 쪼갠 뒤 전체 문자열을 설명에 넣으면 같은 식당의 메뉴끼리 오염된다
(실측: '매생이'가 같은 집 '전복죽'에 medium으로 매칭 → 36건 중 15건이 오탐이었다).

정규화 결과는 redtable과 **동일한 스키마**로 `data/raw/tourapi_{지역}_raw.json`에 저장되므로,
매핑 스크립트가 두 소스를 그대로 함께 읽는다.

```bash
python -m src.collectors.tourapi_region_food --check     # 키·지역코드 확인
python -m src.collectors.tourapi_region_food             # 수집
python -m src.collectors.tourapi_region_food --relabel   # 주소로 시·군구 재라벨 (API 재호출 없음)
```

#### ⚠️ 행정구역 통합 — 광주·전남이 한 시도 코드다 (2026-08-03 실측)

```
전남광주통합특별시 → lDongRegnCd = 12
```

`ldongCode2`가 돌려주는 시도가 하나뿐이라 **수집 단위 라벨로는 광주와 전남이 갈리지 않는다.**
그대로 두면 광주 음식점까지 `region='전남'`, `area_nm='전남'`이 되어 시·군 단위 추천이 불가능하다.

그래서 주소(`addr1`)의 시·군·구 토큰으로 다시 가른다(`split_area`).
광주 자치구 5개(`동구`·`서구`·`남구`·`북구`·`광산구`)를 광주로 되돌리고, 나머지는 전남이다.
실측 결과 **27개 시·군구**로 갈라졌다 (전남 3,184 메뉴 / 광주 710 메뉴).

#### ⚠️ 개발계정 일일 트래픽 1,000건

오퍼레이션당 하루 1,000건이다. 음식점이 **974곳**이라 `detailIntro2` 호출이 한도에 거의 붙는다.
그래서 라벨만 고칠 때는 재수집하지 말고 `--relabel`을 쓴다. 저장된 `road_addr`만으로
재계산하므로 API를 다시 부르지 않는다.

### 지역 축 수산물 보강: 품질인증수산물 (미완)

국립수산물품질관리원 API. **수집기는 삭제했다** (한 번도 동작한 적 없는 스텁이었다).
요청 URL(`http://www.nfqs.go.kr/hpmg/front/api/quality_api.do`)과 제공 정보
(인증종류·품명·업체명·대표자명·주소·사업자번호·전화번호·인증유효기간)는 확인했으나,
**요청 파라미터명과 응답 XML 태그명은 미확정**이다. 사이트의 인터페이스설계서 PDF에 있는데
미리보기가 새 창으로 열려 읽지 못했다. 추측값을 넣으면 조용히 실패하므로 비워 두었다.

가입 후 설계서를 열어 `FIELD_MAP`을 채우면 동작한다. `주소`로 전남·광주를 필터링해
그 지역이 국가 인증을 받은 수산물 품목명을 얻는 용도다.
단 이 API가 주는 건 **생산·가공 업체지 음식점이 아니므로**, 매핑에 바로 조인하지 말고
매칭 어휘 사전으로 쓰는 것이 맞다.

### ⚠️ 대조 실패가 데이터 오류라는 뜻은 아니다

살아 있는 공공데이터가 농사로뿐인데 **농사로는 농산물만 다룬다**(농촌진흥청 소관).
반면 이 엑셀은 전남 해안권 음식이라 수산물이 중심이라, 구조적으로 맞을 수가 없다.
미대조 식재료 27종도 장어·짱뚱어·참게·흑염소·은어처럼 **지역 특산 품목**이라
전국 단위 공공데이터에 애초에 등재되지 않는다. 여수의 `금풍생이`·`물메기`·`삼세기`처럼
그 지역에서만 쓰는 이름도 있어, 표준 품목명 사전으로는 잡히지 않는다.

그래서 보류분을 삭제하지 않고 `food_master_pending.csv`로 남긴다.
지역 API가 열려 메뉴 데이터가 들어오면 재대조해 승격시킨다.

### 지역 표기 정규화

엑셀은 현지 화법을 쓰고(`한우`·`세발낙지`·`물김`) 농사로·수산물표는 표준 품목명을 쓴다.
부위·산지·크기 수식어를 떼서 상위 품목으로 올리는 방향만 허용한다
(`덕자`→`병어`, `보리굴비`→`조기`, `흑돼지`→`돼지고기`). 매핑 표는 스크립트의 `ALIAS`에 있다.
`생선`·`지초`처럼 품목명이 아니라 상위 범주인 토큰은 `SKIP_TOKENS`로 대조에서 뺀다.

출력:
- `data/processed/review/food_master.csv` — 138행 전체 + 등급 컬럼
- `data/processed/review/food_master_pending.csv` — `included=N` 보류분 (109행)
- `data/processed/review/public_only_terms.csv` — 공공데이터/큐레이션에는 있으나 엑셀에 없는 항목 (106 + 19종)
- `data/processed/review/merge_summary.json` — 시각자료용 집계

**이 엑셀은 지역 축 조인 대상이 아니다.** 매핑은 식당 단위(상호·좌표·메뉴설명)로 붙는데
엑셀에는 식당도 좌표도 없다. 매칭 어휘와 지역 귀속 근거로 쓰는 자료다.

## 매핑 규칙

단순 substring 매칭은 오탐이 심해서(식재료 '무'가 상호명 '무등산'에 매칭) 아래 규칙을 쓴다.

1. **상호명에는 매칭하지 않는다.** 메뉴명과 메뉴설명에만 매칭한다.
2. 메뉴설명의 콤마 구분 주재료 토큰과 **정확히 일치**하면 신뢰도 `high`.
3. **1글자 품목은 substring 매칭 금지.** 2번의 토큰 정확일치만 인정한다.
   오탐의 대부분이 여기서 나온다. 실제 데이터에 1글자 농산물 10종
   (`감·귤·무·밤·배·쌀·쑥·잣·조·팥`)과 1글자 수산물 3종(`굴·김·톳`)이 있다.
   특히 수산물에서 이 가드가 결정적이다 — `김`이 `김치찌개`·`김밥`에,
   `굴`이 `굴비정식`(굴비는 조기다)에 걸리는 것을 막는다.

   **예외**: 실측으로 검증한 품목만 `ONE_CHAR_RULINGS`에서 허용한다.
   이 표는 허용뿐 아니라 **차단 결정과 그 근거도 함께 담는다.** 허용 목록만 두면
   "무를 검토했고 107건 전부 오탐이라 막기로 했다"는 판단이 코드에서 사라져,
   다음 사람이 같은 조사를 반복하거나 근거 없이 열게 된다.

   전수 13종 (수집 메뉴 3,894건 기준, 2026-08-04 실측):

   | 품목 | 월 | 히트 | 진짜 | 판정 | 행 |
   |---|---|---|---|---|---|
   | `굴` | 1·2·11·12 | 70 | 11 | 허용 — `굴비`·`굴소스` 제외 | 44 |
   | `쌀` | 10·11 | 12 | 9 | 허용 — `쌀국수` 제외 | 18 |
   | `팥` | 12 | 17 | 17 | 허용 — 예외 불필요 | 17 |
   | `쑥` | 4 | 11 | 11 | 허용 — 예외 불필요 | 11 |
   | `배` | 9·10 | 20 | 5 | 허용 — `뚝배기`·`곰보배추`·`알배기`·`가배` 제외 | 10 |
   | `톳` | 3 | 2 | 2 | 허용 — 예외 불필요 | 2 |
   | `밤` | 12 | 4 | 2 | 허용 — `밤부`·`비빕밤` 제외 | 2 |
   | `무` | 11 | 107 | **0** | **차단** — 전부 무침·스무디·무화과·대나무·무등산 | 0 |
   | `조` | 2 | 103 | **0** | **차단** — 전부 조림·새조개·조기·원조·리조또 | 0 |
   | `김` | 1·2·12 | 49 | 1 | **차단** — 김치·김밥·튀김·`김연수`(상호). 가드가 옳게 동작 | 0 |
   | `감` | 11 | 16 | 2 | **차단** — 이득 2행 대비 예외 7개(감자·감태·곶감·감성돔…) | 0 |
   | `귤`·`잣` | — | 0 | — | 해당 없음 | 0 |

   허용 7종이 **104행**을 만든다. `굴`·`톳`이 +46, 나머지 5종이 +58이다.
   여자만 굴과 나주 배는 지역 대표 특산인데 가드에 막혀 0행이었다.

   기록된 실측치는 수집분이 바뀌면 조용히 낡는다. 재확인 수단을 둔다:

   ```bash
   python -m src.process.build_seasonal_region_mapping --audit-one-char
   ```

   13종의 히트·진짜 건수를 현재 수집분으로 다시 세어 대조한다. 판정을 자동으로 바꾸지는
   않고 어긋난 곳만 알린다. 예외 없이 차단된 품목(`무`·`조`·`감`)의 '진짜' 수는 사람이
   전수 열거해 판단한 값이라 자동 대조 대상이 아니며, 히트 수만 본다.
4. 2글자 이상: 메뉴명 포함 → `high`, 메뉴설명 본문 포함 → `medium`.
5. 농사로 '이달의 음식'명(`fdNm`)이 메뉴명과 겹치면 `match_type='food'`로 따로 기록한다.
   식재료 매칭보다 직접적인 근거다.

6. **다른 음식 이름에 파묻힌 매칭어는 뺀다** (`TERM_EXCLUSIONS`). 2글자 이상이라 3번 가드에
   안 걸리는 오탐이다. 예외 문자열을 메뉴명에서 지운 뒤에도 매칭어가 남아야 인정한다.

   | 매칭어 | 예외 | 이유 | 실측 |
   |---|---|---|---|
   | `보리` | `보리굴비` | 보리굴비는 보리 음식이 아니라 **말린 조기**다 (보리 항아리에 저장해서 붙은 이름) | 54행 중 **34행**이 오탐이었다 |
   | `딸기` | `산딸기` | 산딸기는 농사로에 **6월 항목으로 따로** 있는 다른 품목 | 1행 |

   지운 뒤 판정하므로 `칠게장보리비빔밥`처럼 진짜 보리 음식은 그대로 남는다.
   이 규칙으로 1,927행 → **1,892행**이 됐다 (이후 1글자 7종 허용으로 1,996행).

`match_type`은 `ingredient`(농사로 식재료) / `food`(농사로 음식명) / `seafood`(제철 수산물)
세 가지다. `term_source`로 API 수집분(`nongsaro`)과 큐레이션분(`seafood_curated`)을 구분한다.
